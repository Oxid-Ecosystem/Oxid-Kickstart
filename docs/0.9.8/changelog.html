Changelog

Every notable change to Oxid-DB, per release: features, changes, and bug fixes. These docs describe the current release, 0.9.8.

These docs describe 0.9.8 This site tracks the current release. Use the version selector (top right) to switch between 0.9.8 (current) and 0.9.7 (previous). Features added in 0.9.8 are marked New in 0.9.8 throughout the docs; features that arrived one release earlier carry a Since 0.9.7 badge.

What changed for developers (0.9.7 → 0.9.8)

0.9.8 is a hardening and production-readiness release, not a feature release: it fixes a silent data-loss bug in bulk import, makes bulk-insert validation complete, adds a durability policy for disk failures and an automated restore drill, and makes the memory governor explain itself. No storage-format change, no new MCP tools, no reasoner change. If you build against a 0.9.7 endpoint, these are the differences you can observe from a client:

Upgrade note: one data-loss fix and two new rejections The change most likely to matter is the #325 fix: on 0.9.7, an entity set loaded through POST /import/csv or POST /import/owl could vanish on the next restart under the default delta checkpoint mode (the TBox from the first checkpoint survived, later ABox imports did not). 0.9.8 persists every import; if you re-imported after restarts as a workaround, you can stop. Two requests that 0.9.7 accepted can now be refused: POST /insert/batch returns 400 for the whole batch when any entity's vector has the wrong dimension for its collection (0.9.7 checked only the first and let later ones fail per row), and PUT /config/embedder returns 409 EMBEDDER_MODEL_MISMATCH (and POST /config/apply reports applied:false) when you switch the embedding model on a database that already holds vectors. Both are deliberate: they turn a silent quality problem into a loud, early error.

0.9.8 Current

Released 2026-09-13 (tag v0.9.8), the release these docs describe.

Added
  • Durability policy on fsync failure. [wal].on_fsync_error decides what happens when a durability-critical WAL fsync fails (typically EIO). abort (default) crashes the process so restart plus WAL recovery replays only genuinely durable records, the only posture that cannot re-acknowledge data the Linux writeback-error semantics silently dropped. poison (opt-in) keeps serving reads but latches durability and refuses every later write and commit with 503 UNAVAILABLE until an operator restarts; the latch never clears within a process (prod-01 W1).
  • Automated restore drill. oxd backup drill [<backup>] [--backups-dir <dir>] [--canary <spec.json>] [--max-rpo-seconds N] restores the newest .oxbak or .oxdb-bundle into a throwaway directory, opens it, runs a structural canary (class, individual and vector counts, a vector self-search round-trip, a consistency check), and reports the RPO (the age of the backup: now minus its modification time). It exits non-zero on a restore failure, a canary miss, or an RPO breach, and --json emits the full report. An opt-in in-process worker ([backup.drill], off by default: enabled, interval_hours 24, backups_dir, max_rpo_seconds) runs the same drill on a timer and publishes oxdb_restore_drill_last_rpo_seconds, oxdb_restore_drill_last_duration_ms, oxdb_restore_drill_last_total_vectors, oxdb_restore_drill_last_success_ts and the counter oxdb_restore_drill_failures_total (prod-01 W6). A backup nobody has restored is a hypothesis, not a backup.
  • Embedder model-mixing guard. PUT /config/embedder now refuses, with 409 EMBEDDER_MODEL_MISMATCH, to switch the embedder to a different provider:model identity while the database already holds vectors, because two models of the same dimension would silently share one space and degrade recall. Re-applying the same model is allowed; an empty database is allowed; a database whose stored vectors have no known model identity (manual vectors) is allowed with a warnings[] entry, since the no-mix guarantee can only hold from that point on. The identity excludes the Ollama endpoint URL and the dimension (prod-05 W6).
  • Memory admission driver. GET /ready and the budget object of GET /admin/memory carry admission_driver: "estimate" when the logical live-data estimate is what crossed a watermark (delete data to recover) or "rss" when real process RSS is the floor (allocator retention or an undersized container, so deletes will not free it: raise [server.limits] max_memory or restart). The 507 soft and hard messages say which one applies, and a new gauge, oxdb_memory_admission_driver (0 = estimate, 1 = rss), exposes it to Prometheus.
  • OxQL: verbatim IRIs in IS-A. ?x IS-A <http://data.europa.eu/esco/occupation/0e2d-24d0-4b73> accepts an angle-bracketed IRI carrying any character the bare identifier set excludes (hyphens, ~, %). The bare form is unchanged, the AST is unchanged, an empty <> is a parse error, and rendering re-brackets only when needed.
  • OxQL: bare NEAR resolves the sole collection. NEAR ?x TO … with no .collection qualifier and no configured default now searches the one collection that exists instead of a phantom default. With no collections at all, or several and no default, the error tells you to qualify the stage and lists the available names; EXPLAIN reports the same choice (#371).
  • Bundled demo “Tech Concepts (Vectors Only)”. A third installable demo, tech-concepts: 133 short concept definitions, each a real OpenAI text-embedding-3-small 1536-dimension vector, with zero ontology classes. It shows Oxid-DB as a drop-in vector store you can layer reasoning onto later without re-ingesting a vector. Listed by GET /demos, installed by POST /demos/tech-concepts/install, and offered in the web UI first-run modal.
Changed
  • POST /insert/batch honours a per-entity collection (#370). The effective collection is resolved per entity (entity.collection → batch-level collection → database default), so one batch can target several collections; on 0.9.7 the per-entity key was silently dropped, which produced a confusing collection not found: default on a freshly provisioned server. The up-front validation now scans every vector-bearing entity against its own target: a dimension mismatch, or a fallback to a default collection that does not exist yet, is a 400 for the whole batch naming the offending entity (<iri>: vector dimension mismatch: expected N, got M); 0.9.7 checked only the first vector. A named collection that turns out to be missing stays on the best-effort per-row path (200 with ok:false and an errors list). The per-entity key is a wire-level field: the typed BatchEntity shapes in the SDKs do not declare it yet, the Python SDK's dict-based insert_batch passes it through.
  • Web UI graph polish. A selected individual renders as a solid centre dot, a gap, then a detached dashed ring (also used for a plain focus); property rows in the entity drawer stack the predicate name over its value pill with the retract control on the right, so a long IRI no longer crushes the pill; the class-first similarity reveal clusters revealed neighbours in a ring around the reference and frames it, so the cutoff slider has a visible effect.
  • Memory governor messages are honest about the driver. A 507 now says whether the estimate or the process RSS crossed the watermark and what will actually recover it; previously every message suggested deleting data even when allocator retention was the cause.
  • The Node SDK (@oxiddb/node) is bumped to 0.9.8 in lockstep with the server. The JSON wire contract is byte-stable apart from the new admission_driver field, the per-entity collection on /insert/batch, and the new 409 / 503 cases above, so a 0.9.7 client works unchanged. The Web, Python, Go, Java, .NET and PHP SDKs are not changed in this release.
  • Internal: the oxd-io crate. An injectable clock and filesystem seam threaded through the WAL, the checkpoint writer, and the cold-f32 spill, so disk faults (ENOSPC, EIO) are testable end to end. Production uses a zero-overhead pass-through; durability ordering is byte-for-byte unchanged (prod-06 W1).
Fixed
  • Silent loss of bulk imports under the default checkpoint mode (#325). POST /import/csv and POST /import/owl mutate the ontology in memory without logging to the WAL (a bulk import would flood it) and rely on the next checkpoint to capture the whole effect. Under the default delta mode that checkpoint folded only the committed WAL tail, which is empty for an import, so the import was a no-op on disk and disappeared on reopen: GET /individuals/<iri> went from 200 to 404 and IS-A results emptied. Both routes now force a whole-world base rewrite and fold the superseded delta chain into it (checkpoint_after_bulk_import); full mode is byte-for-byte unchanged. Regression tests cover both routes, a post-delta import, and full mode.
  • Web UI graph freeze on a large class backbone (#372). A many-class, few-individual ontology (roughly 11k classes) froze the graph view: the whole class backbone was added at once and laid out by a synchronous animated layout on the main thread. The view now renders backbone-first with count badges, drops layout animation above a node-count cap, and above a higher cap replaces the chosen layout with a static breadth-first pass and a one-time toast. Small graphs are byte-for-byte unchanged (Phase 0 guardrails).

0.9.7 Previous

Released 2026-09-09.

Added
  • First-class geospatial. A GeoPoint document field type (the JSON sentinel {"$geo":{"lat":<num>,"lon":<num>}}, latitude before longitude), OxQL ?x.field WITHIN <d>{km|mi|m} OF (lat, lon) radius filtering and SORT DISTANCE(?x.field, (lat, lon)) nearest-first ordering (great-circle Haversine, results carry distance_m), and a typed POST /collections/{name}/geo-search convenience route over the same query AST (geo-01/02/03).
  • Spatial grid index. An opt-in equirectangular grid index over a GeoPoint field that generates a candidate superset and then refines it with exact Haversine distance. Its definition persists (format v12) and its contents rebuild on load; the superset invariant means it only makes a query faster, never changes the answer (geo-04).
  • Geo map view. A standalone Leaflet map at /app/geo-map, reached from a document’s location cell in the web UI, that plots a collection’s points and highlights the opened document.
  • Reasoner: role chains and transitivity. Length-2 role chains (r∘s ⊑ t) and transitivity (Trans(r), which desugars to the self-chain r∘r ⊑ r) are now reasoned via the CR8 completion rule, on by default (reasoner-06, card-10 gate passed 2026-09-09).
  • Reasoner: role axioms authorable end-to-end. POST /actions/add-axiom gains the subproperty kind (a governed length-1 role hierarchy sub ⊑ sup), matched across the SDKs (Node AddAxiomRequest, PHP AddAxiomRequest::subproperty()), the MCP add_axiom tool, and lossless OKF export (x-oxid-role-axioms). ObjectPropertyDomain(r, C) is now reasoned as ∃r.⊤ ⊑ C (reasoner-09).
  • Native import formats. POST /import/owl now accepts OWL Functional Syntax (.ofn), OBO 1.4 (.obo), OWL Manchester Syntax (.omn), RDF Turtle (.ttl), and N-Triples (.nt) in addition to OWL/XML, detected by extension or content sniff and overridable with ?format= (owl-expand-01).
  • MCP geo_search tool, bringing the agent surface to 13 tools (geo-03).
  • Installable “A Reasoned Family” demo in the first-run load-a-demo modal: individuals asserted only as Male/Female and Parent are realized into Father/Mother through Father ≡ Male ⊓ Parent, shipped with OpenAI 1536-dimension vectors.
Changed
  • Role chains default on. OXD_REASONER_ROLE_CHAINS now defaults to enabled; set it to 0 to reproduce the 0.9.6 inference set. With chains off, stored chain axioms are loudly reported as inert by GET /reasoner/fragment.
  • On-disk format version 11 → 12. v12 adds GeoPoint values and persisted spatial-index definitions. Older files migrate forward (v11 files upgrade with empty spatial-index definitions); a pre-12 binary refuses a v12 file loudly.
  • The Node SDK (@oxiddb/node) is bumped to 0.9.7 in lockstep with the server; the JSON wire contract stays byte-stable apart from the new routes and fields. The Web, Python, Go, Java, .NET and PHP SDKs caught up to 0.9.7 in the follow-up sdk-sync work: all seven now expose geoSearch, the subproperty axiom kind, distance_m on query hits, and the 0.9.6/0.9.7 routes (/reasoner/fragment, /admin/import, /admin/export, ?format= on OWL import).
Fixed
  • Community Edition memory wedge. The CE Docker image now ships the jemalloc allocator. The default glibc allocator retained freed per-query scratch in per-thread arenas, ratcheting resident memory past the memory governor’s hard watermark until the server refused queries with 503. jemalloc returns freed pages to the OS. The fix is scoped to the Docker images; a non-Docker glibc deployment can bound arenas with MALLOC_ARENA_MAX=2.
  • Turtle import no longer 400s on the wrong extension. A valid Turtle body with a .owl extension is now content-sniffed and imported instead of being rejected as malformed XML.

0.9.6 Older

Released 2026-09-08.

Added
  • Reasoner, ABox realization. Individuals now participate in the saturation graph, so inferred class membership propagates to instances (reasoner-02).
  • Reasoner, CR7 role hierarchy. SubObjectPropertyOf axioms are imported, persisted (format v11), and reasoned; a related fact along a sub-property is inferred along its super-property (reasoner-05).
  • Reasoner, structural normalizer for normalization completeness (reasoner-04), and a per-rule EL differential oracle in CI (reasoner-08).
  • Reasoner, loud incompleteness. Fragment counters, GET /reasoner/fragment, and a conjunction-gap flag report exactly which axioms were skipped instead of silently ignoring them (reasoner-07).
  • Embedding cache. A CachedEmbedder on the live path with memory accounting, [cache.embedding] configuration, and /metrics + /admin/memory stats, enabled by default (embcache-02…06).
  • MCP security. Inbound authentication enforcement and an exposure gate for the MCP server, plus copy-paste client config on key mint (mcp-sec-01/02).
  • Whole-database snapshots. Full-fidelity .oxdb-bundle backup/restore, and live-server POST /admin/import · GET /admin/export with boot-time promotion and a working Restore/Export in the web UI Data page (snapimport-00/01).
Changed
  • Expressivity claim tightened. The reasoner is now documented as OWL 2 EL⊥ (a subset of EL++); the aspirational “EL++” label was removed and a claims gate added (reasoner-11).
  • MCP tool count corrected to 12 (documentation drift fixed) (mcp-sec-03).
  • Single-file backup refuses lossy runs by default: POST /backup returns 422 BACKUP_WOULD_LOSE_DATA when paged documents or KGE models would be dropped; pass allow_partial to override (snapimport-00).
  • The Node SDK (@oxiddb/node) was bumped to 0.9.6 in lockstep with the server. The Web SDK stayed at 0.9.4 for this release; it and the other language SDKs caught up to 0.9.7 in the sdk-sync work (see the 0.9.7 notes above).
Fixed
  • Fuzzing. The dict_decode fuzz target is hardened: a hostile next_id could burn the fuzz clock; the slot walk is now capped.

0.9.5 Older

Released 2026-09-05.

Added
  • Ingest, EL⊥ clash-at-close gate. An opt-in validate_consistency flag makes a bulk import into an auto_type collection reject the whole batch atomically if it would make the ontology inconsistent (ING-5).
  • Ingest benchmarks. A cross-component equivalence gate and a mixed document+vector+ontology ingest-timing backbone (ing-08, ing-09).
  • High availability, cheap wins. The server now honours oxd.toml group-commit knobs, with a nightly determinism gate.
  • Internationalisation. The whole web-next UI is translated (English + Dutch), plus a Simplified Chinese (zh) locale.
Fixed
  • Replication determinism. Deterministic HNSW levels + re-election, a canonical free-list, and two-node WAL-replay determinism oracles (repl-01…05).
  • KGE ModelStore replica gap: trained models are now reproduced on replicas (repl-06).
  • delete_individual SQ8 pending deletion path corrected.
  • Integrity gates. SQ8 + binary dirty-read regression gates added (integrity-01).

0.9.4 and earlier

0.9.4 (2026-09-01) and prior releases established the core: the shared Term model, the OWL EL⊥ reasoner, off-RAM cold-f32 vectors, the JSON document store and ontology bridge, transactions, authentication, and the SDK family. Full commit history lives on GitHub.

How versions map to your deployment Installation and upgrades are managed for you while Oxid-DB is closed-source, so you are normally on the current release (0.9.8). The version selector and this changelog exist so you can tell exactly which behaviour a given endpoint has.
